# 回源在认领后脱离领头请求的取消，并去掉它的 GORM 事务

一次回源服务的是这个 key 的**所有**等待方，但认领它的只是其中一个请求。所以认领成功后，整个回源（包括二次检查）用的 ctx 是：保留领头请求 ctx 里的值（trace 等），去掉它的取消和截止时间，并去掉 `WithGORMTx` 放进去的事务。二次检查和向上游取值各自受 `WithFetchTimeout` 限制。

## 以前的问题（main 也是如此）

- 二次检查用的是领头请求的原始 ctx。领头请求一放弃，二次检查就因为 ctx 已取消而失败，然后照样去上游取值：缓存里明明已经有值，还是多打了一次上游。
- 回填时如果后端是 GORMCache，会用到领头请求放进 ctx 的业务事务。这个事务一旦已经结束，回填就会失败；如果事务还在进行，回填会跟着它一起提交或回滚。

## 考虑过的方案

- **只去掉事务，取消的时机不变**：解决不了领头请求放弃导致的多余回源。
- **连 ctx 里的值也全部去掉**：trace 就断开了，而且没有通用的办法只保留一部分值。

## 后果

- 领头请求的 ctx 结束时，它自己立即返回，回源继续为其他等待方服务。这一点和以前相同。
- 二次检查有了独立的超时，不会无限期挂在一个卡住的后端上。
