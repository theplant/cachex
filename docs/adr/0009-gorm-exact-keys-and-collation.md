# GORMCache 只认完全相等的 key，MySQL 建表用 utf8mb4_0900_bin

缓存 key 区分大小写和末尾空格，但 MySQL 默认的排序规则（`utf8mb4_0900_ai_ci`）既不区分大小写、也不区分重音。在 main 上，`Set("ABC")` 之后 `Get("abc")` 会读到 `ABC` 的值，而 upsert 又不改写主键列，于是 `Set("abc", x)` 会把 x 写进 `ABC` 的那一行。我们做了三件事：

1. `Get`/`GetMany` 只返回存储的 key 和请求的 key 完全相等的行；
2. upsert 时连同 key 列一起改写，一行共享的数据只属于最后写入它的 key；
3. `Migrate` 在 MySQL 上建表时使用 `utf8mb4_0900_bin`，大小写和末尾空格都精确比较。这要求 MySQL 8.0.17 及以上（MariaDB 没有这个排序规则），所以建表前会先检查版本。

前两点保证不管表用什么排序规则，**都不会读到别的 key 的值**；第三点让新表从根上避免冲突。

## 考虑过的方案

- **大小写不敏感地匹配，和 `Get` 保持一致**：这是本 PR 的一个中间版本。它只是让 `GetMany` 和 `Get` 错得一样，读到别的 key 的值这个问题依然存在。
- **`utf8mb4_bin`**：支持更老的 MySQL，但它是 PAD SPACE 排序规则，会忽略末尾空格，`"a"` 和 `"a "` 仍会共用一行。我们选择只支持 MySQL 8.0.17 及以上。
- **改写已有表的排序规则**：会对老用户的表执行 ALTER，风险不应由库来承担。已有的表保持不动，README 给出了手动转换的语句。

## 后果

- 老表上只差大小写的几个 key 会互相挤占同一行，表现为多几次未命中，但不会串值。
- 不再支持在 MySQL 8.0.17 以下的版本和 MariaDB 上**新建**表；已经存在的表照常可以使用。
