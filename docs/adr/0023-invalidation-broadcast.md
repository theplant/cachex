# 失效广播：只删本地层，经过守卫，订阅成功就清空

租约挡住了共享层的旧值回填（[ADR 0020](0020-leases-on-shared-layers.md)），但一个实例的写入仍然到达不了其他实例的内存层，它们一直返回旧值，直到条目腐烂。我们加上可选的失效广播：

- **传输可插拔**：核心包定义 `Broadcast`（`Publish` 发字节，`Listen` 收字节，每次订阅成功调用 `ready`），消息编码由核心包负责。Redis Pub/Sub 和 go-bus 各一个实现：前者延迟低、断线丢消息，后者给不想引入 Redis 的项目。
- **只删本地层**：「本地」是后端的属性，由后端实现可选接口 `LocalBackend`（`Clear`）来声明，otter、BigCache 实现，Redis、表不实现。共享层由写入方写过了，广播从不碰它；收到的消息等分片等到超时放弃时，分片空出来之后也只删本地层。
- **收到的 key 经写入顺序守卫删除**：拿分片写锁、摘除在途回源、写入代数 +1，和本地写入一样。
- **每次订阅成功就清空本地层**，包括启动时的第一次：漏了哪些消息不知道，就全部作废。清空时拿住全部分片，免得重连前开始的回源在清空之后回填。
- **忽略自己发出的消息**；**发布失败不让写入失败**，重试两次后仍失败记 ERROR（见下文修订）。

## 考虑过的方案

- **层上加一个「本地」选项**：使用者可能把 Redis 层标成本地，广播一来就把共享层删了。本地与否是后端天生的属性，而清空本来就要后端支持，所以合成一个可选接口。
- **只用 go-bus**：它的广播是每个实例一个队列，每条消息往 N 个队列各插一行再删掉，消费者还要轮询，延迟几百毫秒，负担压在业务数据库上；可靠投递在这里用处不大，因为丢消息可以靠清空本地层兜住。但不想引入 Redis 的项目需要它，所以两个都做，由使用者选。
- **收到后直接删后端**：这个实例上更早开始的回源会在删除之后把旧值回填回来。
- **丢消息就等 TTL**：丢了等于没开广播；清空本地层把代价换成重连后一段时间多读共享层，不会读到旧值。
- **记一个「清空时刻」、读到更早的条目就当未命中，代替真的清空**：条目记的是数据源的回答时间，从共享层复制上来的条目会被永远当成过期。
- **发布失败让写入返回错误**：各层已经写好，回滚没有意义；发布失败多半是连接断了，那时其他实例也在重连，会清空本地层。

## 后果

- 开了广播必须至少有一个本地层，否则 `New` panic。
- 订阅成功时清空会让写入短暂排队（拿全部分片），读取不受影响；重连后内存层是冷的。
- 写入多一次发布（同步，写完各层之后）；没开广播时写入路径没有变化。
- 收到广播的删除经过写入顺序守卫，和本地写入一样：删除之后，这个进程不会再读到被删的旧值（[ADR 0022](0022-reads-never-go-back.md)）。

## 修订（2026-10-15）

上面「发布失败多半是连接断了，那时其他实例也在重连，会清空本地层」这个前提不成立。一次体检在部署「内存 → PostgreSQL → 数据源、go-bus 广播」上复现：数据库断开所有连接之后，写入方的写入换了新连接成功，发布却用到一条池里已经断开的连接，失败；其他实例的订阅没有过期，go-que 在内部重连，不会重新订阅，也就不清空本地层，于是一直读到旧值，直到内存层的 TTL。改为：

- **发布失败重试两次**（间隔 100ms、200ms，受一个回源超时约束）；一条消息失败，后面的消息照发；仍然失败记 ERROR。仍不让写入失败：各层已经写好，调用方重试写入也补救不了其他实例。发布最终失败时，其他实例读旧值的上限是它们内存层的 TTL，README 和 [consistency.md](../design/consistency.md) 如实写明。
- **补做的删除放开分片之后再发布**：它原来拿着分片发布，而重新订阅时的清空要等所有分片；发布慢（或者像 `cachextest.Bus` 那样等监听者腾出缓冲）时，两边互相等，这个实例的写入被堵住。普通写入本来就是放开分片之后才发布。
- **gobuscachex 发布时屏蔽调用方的事务**：go-bus 从 ctx 里取事务（`bussql.NewContext`），调用方按惯例用同一个 ctx 改完数据源、提交、再写缓存时，发布会跑进已经结束的事务而失败，事务没结束时还会跟着它回滚。消息是缓存自己的，和 [ADR 0007](0007-detached-fetch-context.md)、[ADR 0017](0017-gorm-never-joins-a-caller-transaction.md) 一样不进调用方的事务。
