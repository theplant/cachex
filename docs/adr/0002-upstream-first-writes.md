# Set/Del 先写上游，任何失败都删掉本层条目

`Set`/`Del` 先写上游、成功后再写本层；任何一步失败，都删掉本层这个 key 的条目和不存在记录，然后返回错误。理由是：上层不能出现下层没有的值。如果先写本层、上游却写失败了，本层就会一直挂着一个「从未真正发生过」的值，直到 TTL 到期。上游写失败时，它的状态是未知的（可能已经写进去了，只是回复丢了），所以本层不能猜，只能删掉，让下次读取回源取真实状态。

## 考虑过的方案

- **先写本层（main 的做法）**：写入一返回，本层马上可见；但上游失败时会留下本层有、下层没有的值。
- **只删本层、不写本层（cache-aside 的经典做法）**：删除总是安全的；但 `Set` 之后的第一次读必须回源。在「上游不是 Cache」的用法里（先改数据库、再 `Set`），`Set` 就退化成了 `Del`，失去了意义。分片锁已经保证了写入顺序（[ADR 0003](0003-striped-backfill-guard.md)），写本层是安全的，所以保留写入。

## 后果

- 写入过程中有一个短暂窗口：本层自己的写入落下之前，并发读本层仍会读到旧值。`Set`/`Del` 返回后窗口关闭。
- 上游写成功、本层写失败时，返回错误，但上游的改动**不回滚**。返回错误不代表什么都没写进去。
- `Del` 失败时不会记下不存在，因为上游可能还留着这个 key。
- 这是相对 main 的行为变化，已写进 PR 描述的行为变化表。
