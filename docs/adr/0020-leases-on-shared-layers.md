# 共享层用租约挡住旧值回填

[ADR 0011](0011-cross-instance-consistency-via-ttl.md) 把多实例下的旧值回填交给 TTL 兜底，租约放进待办。旧值回填进共享层的后果比其他实例的内存层看不到写入严重得多：它活整个共享层的 TTL，而且所有实例的内存层都会从共享层把它复制下去。所以共享层的 TTL 只能设短，命中率跟着受限。

现在加上租约：

- **后端可选实现**，开关在后端自己的配置里，默认关闭。`Backend` 可以实现 `Leasing`，它的 `Leaser()` 返回 nil 就是没开；字节后端对应 `ByteLeasing`，由 `Encoded` 转发。核心包只认接口，仍然不认识任何后端。
- **一层未命中之后才领租约**，在往下读之前：第一层在二次检查之后领，下面的层在它未命中之后领。命中路径不多一次往返。读和领租约不需要是同一个原子操作：只要先领租约、再读下层和数据源，之后的任何写入都会让令牌作废；两步之间插进一次写入，代价只是多回源一次。
- **写入作废租约**：开了租约的后端，`Set`、`SetMany`、`Del`、`DelMany` 都要结束这个 key 的租约。
- **回填只写还持有令牌的层**，用 `PutLeased`，写完结束租约；「不存在」要删除时也带令牌。没拿到令牌的层不回填，它上面不开租约的层（比如进程内的内存层）照常回填。
- **没用上的令牌释放掉**：回源失败、被进程内的写入跳过回填时，一次回源结束后把剩下的令牌一起 `Release`。
- **租约的有效期是 `WithFetchTimeout`**：持有者崩溃时租约自己过期；回源加回填本来就被它限住。
- **别的实例持有租约时**，普通读取照样回源、返回结果，只是不回填那一层；后台刷新则跳过数据源，交给持有者去刷新，下一次陈旧命中会再试。领租约失败（调用出错、这一层存不下这个 key）不算别人持有，刷新照常回源，否则这个 key 在整个陈旧期里都不会刷新。
- **多个共享层各自领租约**，各自校验自己那一层的回填。

## 考虑过的方案

- **读和领租约合成一次往返（Lua）**：未命中时省一次往返，但这一层所有的读都要走脚本，命中也付成本；数据库后端也很难合成一次。原子性又不是必需的。
- **`Cache` 上加一个总开关**：租约的代价（多一个 key 或一列、Lua、迁移）都在后端，由后端决定最自然；核心包只看接口。
- **只让最上面的共享层领租约**：下面的共享层留一个不防旧值回填的洞。
- **拿不到租约就等待、轮询**（跨实例的回源去重）：要决定等多久、超时后怎么办，是另一个功能。现在只做刷新跳过，它几乎不花成本。

## 后果

- 打开租约的共享层，能看到旧值的最长时间只剩其他实例内存层的 TTL，共享层的 TTL 可以设长。
- 每个开了租约的层，未命中时多一次往返（领租约），回填改用 `PutLeased`；回源失败时多一次 `Release`。没有任何层开租约时，读路径只多几次 nil 检查。
- `Leaser` 的契约测试是 `cachextest.TestLeaser`；`cachextest.NewLeasingMap` 是内存里的实现，用来模拟多个实例共用的层。
- 为了让 Redis Cluster 上的租约 key 和数据 key 同 slot，`Cache` 拒绝含 `}` 却没有 hash tag 的 key，见 [ADR 0019](0019-core-rejects-keys-without-a-redis-slot-for-their-lease.md)。
